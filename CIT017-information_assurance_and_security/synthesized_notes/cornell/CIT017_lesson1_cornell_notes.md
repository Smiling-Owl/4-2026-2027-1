# Information Assurance and Security: Foundations (Cornell Notes)

| Cue / Keywords | Notes |
| :--- | :--- |
| **1. The McCumber Cube**<br><br>- What is the McCumber Cube?<br>- What are the three information states?<br>- What does the CIA Triad stand for?<br>- How are countermeasures categorized? | - **Definition**: A 3D framework used to evaluate information system security by analyzing the interaction between three dimensions.<br>- **Information States (Data Status)**:<br>- *Transmission (Data in Motion)*: Data traveling over a network (e.g., sending an email).<br>- *Storage (Data at Rest)*: Data sitting on a hard drive or database.<br>- *Processing (Data in Use)*: Data currently being updated or calculated in RAM.<br>- **Security Goals (The CIA Triad)**:<br>- *Confidentiality*: Protecting against unauthorized disclosure.<br>- *Integrity*: Protecting against unauthorized modification.<br>- *Availability*: Ensuring timely and reliable access.<br>- **Countermeasures (Protection Methods)**:<br>- *Technology*: Hardware and software (e.g., Firewalls, Encryption).<br>- *People*: Awareness, training, and ethics.<br>- *Policies & Practices*: Standard Operating Procedures (SOPs), laws, and rules. |
| **2. Foundations of Information Security (Functional Controls)**<br><br>- How is security practically applied?<br>- What are the three main functional controls? | - **Prevention**: Stopping the attack before it happens (e.g., keeping an asset physically locked away).<br>- **Detection**: Identifying that an attack is happening or has already happened (e.g., checking logs or using motion sensors).<br>- **Mitigation (Response)**: Limiting the damage once an incident is detected (e.g., reporting a loss or isolating a virus). |
| **3. The AAA Framework**<br><br>- What is the AAA Framework?<br>- What are the three authentication factors?<br>- Why is accounting important? | - **Authentication ("Who are you?")**: Proving identity.<br>- *Factors*: Knowledge (Password), Possession (OTP/Token), Inherence (Biometrics).<br>- **Authorization ("What are you allowed to do?")**: Defining permissions.<br>- *Example*: A student can view their profile but cannot edit the grade database.<br>- **Accounting / Auditing ("What did you do?")**: Tracking user actions.<br>- *Non-repudiation*: Ensures a user cannot deny performing an action because the logs provide definitive proof. |
| **4. Key Security Principles**<br><br>- What are the core security principles?<br>- What is the difference between Least Privilege and Need-to-Know?<br>- What is Defense in Depth?<br>- Why is Open Design better than Security through Obscurity? | - **Least Privilege**: Give users only the minimum permissions necessary to perform their job.<br>- **Need-to-Know**: Having clearance does not guarantee access; data is only accessible if required for the current task.<br>- **Separation of Duties**: Splitting a sensitive task between two people to prevent fraud (e.g., one requests a check, another signs it).<br>- **Defense in Depth**: Employing layered security (e.g., if a firewall fails, host-based antivirus serves as a backup).<br>- **Fail Safe (Security by Default)**: If a system crashes, it must fail into a "locked" state, not an "open" state.<br>- **Security by Design**: Security is integrated into the software from the very first line of code, not added as an afterthought.<br>- **Principle of Complete Mediation**: Every access to every object must be checked for authority (no shortcuts after the first login).<br>- **Economy of Mechanism**: Keep security design simple and small to reduce the "attack surface".<br>- **Open Design**: Security should not rely on the secrecy of the design (avoid "Security through Obscurity"). The system must remain secure even if an attacker knows how it works (e.g., AES encryption). |
