# Systems Integration Drivers

**Date:** 2026-08-15

| Cue / Keywords | Notes |
| :--- | :--- |
| **Integration Driver** | A business need or organizational pressure that creates a reason to connect systems, share data, or redesign workflows. Drivers explain **why** integration is undertaken. |
| **Signs Integration Is Needed** | - Information from several systems must be collated in real time.<br>- Many systems need to communicate.<br>- The same details must be entered or updated in separate systems.<br>- Extracting information across systems is difficult or slow.<br>- Data is transferred through batch uploads.<br>- Information is duplicated or inconsistent across systems. |
| **Project vs. Organizational Drivers** | - **Project drivers:** Specific business capabilities or technical outcomes that an integration initiative must deliver.<br>- **Organizational drivers:** Broader external or structural forces that compel the organization to integrate or reorganize its systems. |
| **E-Business** | Connects legacy systems containing core business functions to web-facing systems such as application servers and portals. |
| **E-Government** | Enables workflows and data exchange within and between government agencies. |
| **Business Intelligence** | Integrates data from multiple sources so it can be mined for patterns and trends. |
| **Customer Expectations** | Provides customers with immediate access to real-time services and information. |
| **Customer Relationship Management** | Integrates customer databases, call centers, and web-based customer-service systems to create coordinated customer interactions. |
| **Knowledge Management** | Connects systems that capture, organize, share, and preserve an enterprise's knowledge assets. |
| **Customer Self-Service** | Integrates customer-facing systems so customers can perform services previously handled by employees. |
| **IT System Consolidation** | Migrates applications and network services from multiple computers or platforms to fewer, centralized systems. |
| **Supply Chain Management** | Exchanges real-time information between buyers and suppliers to optimize the supply chain and streamline workflows. |
| **ERP Expansion** | Integrates the organization's core enterprise resource planning system with specialized systems that provide additional functions. |
| **Industry Regulation** | Laws and industry rules may require standardized data exchange, security, confidentiality, or reporting. HIPAA is presented as an example involving healthcare EDI, security, and privacy. |
| **Globalization** | Requires processes and workflows to operate across organizational and regional boundaries. |
| **Consolidation, Mergers, and Acquisitions** | Creates a need to merge duplicate or overlapping systems that perform similar functions. |
| **Industry Deregulation** | Can drive large monolithic systems to be divided into smaller, more manageable systems connected through loose integration. |

---

### Summary
Systems integration begins with a driver: a concrete project need or a wider organizational pressure. Project drivers include e-business, e-government, business intelligence, customer services, knowledge management, consolidation, supply-chain coordination, and ERP expansion. Organizational drivers include regulation, globalization, mergers and acquisitions, and deregulation. Repeated entry, duplicated or inconsistent data, slow extraction, batch transfers, and demand for real-time information are practical signs that integration is needed.
